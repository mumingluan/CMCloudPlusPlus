# 对象库创建与管理

## 0.1.7：共用文件浏览与传输

对象库与普通文件夹共用 App.tsx 的列表／网格、选择、排序、筛选、搜索、右键菜单和操作弹窗。进入对象库后隐藏“新建对象库”，增加“管理对象库”“退出对象库”。复制、移动、重命名、删除和建目录由 SDK 提交；批量复制／移动复用原 blob 引用，不调用云盘复制／移动接口。上传、下载保留目录结构与空目录，下载为本机不兼容、大小写冲突或已存在的名称选择安全名称。

上传／下载进入原持久传输列表，支持原有暂停、继续、取消和重启恢复。上传发布保留原 nonce、父提交及对象引用，响应丢失后恢复同一提交。加密上传先显示加密进度，再显示真实确认上传字节；加密下载先完整取得并校验密文，随后显示解密进度，完整明文 SHA256／认证通过后才发布最终文件。加密任务共用暂存额度，不扩大空间保护线。

加密预览通过该队列取得并解密到应用私有临时文件，只授权这一份已验证输出给原预览控件。关闭时撤销授权并请求回收，中断后的预览在下次启动清理。本机临时播放链接不提供复制；云端加密对象链接指向密文，需要凭据读取。

设置中的 AxuanStor 区域可查看库名、GUID、清单缓存大小并删除缓存，使用中的库受保护。只清派生数据库／元数据缓存，保留观察 pin、真实 SDK 会话、上传／改密检查点和用户导出文件。删除全部本机对象库凭据需要两次确认，先停止相关任务并关闭会话，再清保存的密码／密钥与 Android 对象库 Keystore 密钥；云盘账号仍保留。系统备份、其他设备及存储介质副本不属于此操作的擦除范围。

### 加密与凭据变更的边界

新密码包装器使用 Argon2id v19，416 MiB、6 轮、1 lane、64 字节盐，工作因子与 [VeraCrypt 默认 Argon2id 参数](https://veracrypt.io/en/Argon2id.html)一致。Rust 大内存派生串行化并清零工作区，AES／AEAD 和敏感缓冲启用清零；内存不足时拒绝，不自动降级。Windows AES-NI 与 ARM64 APK 的 ARM AES 路径按 CPU 能力选择，保留常数时间软件回退。没有 Android 真机吞吐测量或独立密码学审计，不把参数和构建验收当作整体安全性认证。

改密／换密钥重新包装同一个数据主密钥。已解锁设备或持有旧凭据及旧包装器副本的设备仍可能读取历史内容，与 [VeraCrypt 旧卷头副本的访问边界](https://veracrypt.io/en/Changing%20Passwords%20and%20Keyfiles.html)相同；不是撤销全部历史访问或全库主密钥轮换。

### 本机完整缓存作为 Compact 来源

完整 SQLite 索引携带绑定库、marker、inventory、已观察 pin 和语义的私有完整性证明。只有完整且验证匹配的索引可作 Compact 最终视图来源，部分目录或只重写普通校验和的数据库会被拒绝。原始提交精确字节与因果继续由已验证元数据缓存／压缩档案证明；仍检查云端新提交，缺少必要原始元数据时回源，不凭数据库伪造原提交。

导航复用短期 inventory，手动刷新与写入强制检查；一次刷新不重复列举全库提交。不可变元数据使用 LRU，命中触碰合并到 30 秒窗口，不删除真实检查点。下文旧吞吐数据为历史基线，不是新版本真机承诺。

0.1.7 两个发布包、测试和验收范围记于 `REPOSITORY-RELEASE-20261111.json`。Windows 窗口验收由用户延后，现有 GUI／账号库未替换；ARM64 APK 尚无手机安装、Keystore 或触屏验收声明。

## 早期实现与历史验收

桌面文件工具栏、手机添加菜单均有“新建对象库”。选择名称和普通／加密类型；加密库支持密码、导入 32 字节密钥或生成并导出密钥文件。确认密码后才提交。取消密钥导出不会继续创建对象库，界面只持有原生层返回的临时密钥句柄。

对象库文件夹的三点菜单提供“管理对象库”，库内也可进入管理。管理页显示库 ID、类型及当前解锁方式；新建加密库可修改密码或替换密钥，并可移除本机保存的解锁材料。修改一种方式会保留另一种方式。普通库没有密码／密钥操作。提交或系统密钥选择器未结束时，相关输入和关闭操作暂时锁定，结束后恢复。

新建加密库把凭据签名策略固定在不可变 marker 中。后续密码／密钥变更发布带因果父引用的签名凭据记录，不修改原 marker，也不重新加密或上传已有载荷。云端响应不确定时，本机私有检查点保留原签名字节及原上传身份；重新打开先恢复已确认凭据版本，再解锁。重试必须使用同一次变更的新密码或密钥，不能用另一份材料覆盖未确认操作。

早期没有凭据签名策略的加密库仍可读取，但管理页会明确显示其修改能力限制；本次不覆盖旧 marker 来强行升级格式。改密码或密钥更新的是主密钥包装，已经持有旧主密钥或历史内容的参与者仍可能读取其历史副本。请保留导出的密钥文件；本机保存功能使用平台系统秘密存储，不能替代独立密钥备份。

# 目录读取

对象库按账号和库 GUID 保存持久 SQLite 目录索引，数据库保存最终状态、删除项和最小同步标识，不保存原始提交日志。进入目录、打开上级目录和写入前检查云端提交标识；没有语义变化时复用本机目录，有变化时合入已验证的目录状态。部分目录缓存不能冒充完整快照。加密库的索引行独立认证加密，目录键使用 HMAC；缓存损坏只重建派生索引，保留真实 SDK 检查点、上传会话和已观察版本。

普通库可在后台静默生成 Compact 目录检查点。首次存在检查点后，只读根节点和描述文件即可列出根目录，子目录按需加载；写入仍在必要时取得完整最终视图以验证操作。后台维护使用独立 SDK 句柄、持久单次计划和限速，不长时间持有前台库锁。清理前校验完整最终状态、因果覆盖和原始元数据身份，清理只针对已覆盖的提交／清单元数据。原包体及其 FileID 不变。带强签名策略的库继续原有权限规则，暂不自动 Compact。格式说明见 AxuanStor 的 `docs/COMPACT-DIRECTORIES.md`。

不可变元数据仍按账号、目录、FileID、大小和完整摘要缓存；缓存不保存载荷包体、临时签名链接或解锁主密钥。新库仅创建所需基础目录，blob 前缀目录按写入需要生成。

此前真实 x3-client 的全提交读取基线，以合计 1 MiB/s 下载额度测得首次约 178 秒；不可变缓存优化后的旧格式冷读约 101 秒、已有磁盘缓存重开约 1.8 秒。这些属于 Compact 前的测量。当前目录检查点、持久索引与正式包的验收结果另记在实际部署回执中。SDK 视图含控制和验证路径，不能据其记录总数判断全部 Package 传输完成。

与本次实现直接相关的 35 项前端测试、3 项原生定向测试、41 项共享 Rust SDK 测试及 Go SDK／提供者测试通过；Go→Rust→Go 互操作覆盖密码和密钥变更、并发版本拒绝、响应丢失后的原操作恢复和已观察凭据版本。桌面浅色、手机深色的创建／管理／待提交界面通过浏览器检查。Windows／Android 构建与包校验记录另见 `REPOSITORY-RELEASE-20261110.json`。本次没有更换用户正在运行的 GUI、读取其账号库，或对 Android 设备安装验收；实际云端创建和改密操作未作为生产写入测试执行。
